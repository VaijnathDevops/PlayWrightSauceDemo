# Test Cases: Checkout

**Source requirement:** Requirement item #2 (Core Workflow — "a full user journey through the app's primary feature: browse products, add to cart, checkout") and item #3 (Negative/Edge Cases — "at least two tests validating error handling/edge conditions (e.g. empty cart checkout, form validation messages)"), using the requirement's own suggested examples.
**Target app:** https://www.saucedemo.com

**Assumptions:**
- No Page Objects or automated tests existed yet in `SauceAppTests/` at the time this file was first authored, so it originally described the flow using SauceDemo's conventional, well-known structure. All `[TBD]` markers below have since been resolved by inspecting the live app (see "Confirmed against the live app" below) and by the resulting automation in `SauceAppTests/Tests/CheckoutTests.cs`.
- The checkout customer-info form requires First Name, Last Name, and Zip/Postal Code (confirmed live: all three are enforced by client-side validation, each producing its own validation error; all three are directly exercised in automation, along with the positive all-fields-valid path).
- All test cases assume a prior successful login using `TestSettings.StandardUsername` / `.Password`, per the credential-by-role convention established in `TestCases/Login.md`.

**Confirmed against the live app (2026-08-18):**
- The product sort control is a `<select data-test="product-sort-container">` dropdown (accessible role "combobox", unique on the page) with options: "Name (A to Z)" (default), "Name (Z to A)", "Price (low to high)", "Price (high to low)".
- Each product card exposes an "Add to cart" button (becomes "Remove" once added) scoped per product; the cart badge shows the running item count.
- The cart page ("Your Cart") lists added items by name; "Checkout" is a plain-text button.
- The checkout customer-info step ("Checkout: Your Information") has First Name / Last Name / Zip/Postal Code text inputs (placeholder-labeled, no `<label>` elements) and a "Continue" button.
- The order overview step ("Checkout: Overview") lists the same cart items with pricing/total, and a "Finish" button.
- The confirmation page ("Checkout: Complete!") shows an `<h2>` heading reading exactly **"Thank you for your order!"**, with body text "Your order has been dispatched, and will arrive just as fast as the pony can get there!". The cart badge/cart contents are empty immediately afterward.
- **Empty-cart checkout bug (confirmed — see BUG-CHECKOUT-001 below):** the public SauceDemo app does **not** prevent checkout with an empty cart. With zero items in the cart, the "Checkout" button on the cart page remains visible and enabled, and clicking it proceeds normally to the "Checkout: Your Information" step (`checkout-step-one.html`) exactly as it would with items present — it is not hidden, disabled, or blocked. Direct navigation to `checkout-step-one.html` with an empty cart also succeeds. This is a genuine defect in the app, not intended behavior — a cart with no products has nothing to check out, so checkout must not be reachable. TC-CHECKOUT-002 below documents the **correct, intended** behavior (checkout blocked) as its expected result; the corresponding automated test is expected to fail against the live app until the app is fixed, per this repo's self-healing policy (report as a product bug candidate rather than weaken the assertion).
- **Required-field validation text (confirmed):** leaving Zip/Postal Code empty (with First/Last Name filled) and clicking Continue produces the error `Error: Postal Code is required`, rendered in an `<h3 data-test="error">` banner (same element/pattern as the login page's error banner); the user remains on `checkout-step-one.html`. Leaving First Name empty produces `Error: First Name is required`, and leaving Last Name empty produces `Error: Last Name is required`, by the same mechanism.

| BUG-CHECKOUT-001 | Checkout is not blocked when the cart is empty | 2026-08-21 | Medium | Clicking "Checkout" on the cart page with zero items proceeds straight to the "Checkout: Your Information" step (`checkout-step-one.html`) instead of being blocked. Actual: checkout proceeds exactly as it would with items present, and direct navigation to `checkout-step-one.html` with an empty cart also succeeds. Reproduced via TC-CHECKOUT-002 / `Checkout_WithEmptyCart_DoesNotProceedToCustomerInfoStep` in `SauceAppTests/Tests/CheckoutTests.cs`, which encodes the correct expected behavior and currently fails against the live app for this reason. Status: open, not yet fixed by the app.
